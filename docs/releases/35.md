# OurHouse release 35

Receipt AI offers shorter names while retaining the printed label for review. Suggestions are tied to an exact source line and accepted only when supported by the receipt words and retained type/variant qualifiers. Unsupported or conflicting suggestions keep the receipt label. Quantities and prices are not changed by naming suggestions.

Review groups products into Pantry and Household, with a section selector for every item. An opaque label without a supported category keeps its name and asks the user to choose a section before importing. Imports respect the reviewed section, keep different sections separate and retain source-based receipt-line identities for idempotency. All products remain unselected until the user chooses them.

The parser retains supported wrapped qualifiers and fat percentages, handles each-price and tax-code suffixes, excludes sale notices, and guards misplaced quantity rows. Purchased weights remain distinct from a printed “per 1 lb/kg” rate. Receipt AI uses shorter overlapping strips and keeps successfully read sections if another strip needs on-device fallback, including a names-only section whose line totals were omitted. Boundary matching requires distinct agreeing anchors; disagreements retain the first read with a review warning. Source text and per-section evidence stay in the on-device review/export, outside application logs and the public repository.

This is an extraction and review improvement, not model fine-tuning or a guarantee of complete recognition. Faded, angled, abbreviated or unreadable print still requires comparison with the photo. No authentication, database schema or existing household-record migration changes.
