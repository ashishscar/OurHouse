# Release 37 candidate: receipt row recovery

This release carries the receipt parser changes from the GitHub source branch. It keeps the existing OurHouse URL, accounts, database, storage, encryption keys, and notification bindings. There is no data migration or provider change.

The parser now separates purchase labels merged with neighboring count or weight lines only when printed arithmetic supports the split. It keeps original OCR text in each item's review evidence, prevents a loyalty-points footer from becoming stock, and reconciles shifted subtotal, tax, and payable amounts only when the basket and printed tax agree. Receipt import still requires users to review and select items.

Private local diagnostics on five previously opened whole receipts found 90 of 90 purchase rows and 90 of 90 amounts in printed order. Exact raw names were only 75 of 90; this is not a claim of complete OCR accuracy or an independent untouched holdout. The experimental trained OCR model is not included in this release. Phone end-to-end latency remains unmeasured.

The exact release candidate passed the full local release validation, including tests, TypeScript, production build, startup-size budget, and Worker dry runs. Isolated staging, production version recording, rollback dry run, and public smoke checks are required before promotion. The previous production release is 36.
