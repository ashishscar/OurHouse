# OurHouse web release 18

The interactive user guide opens from More and Settings, with search, saved reading checklists, guided steps, download and explicit navigation to app screens. The same public instructions are available at /user-guide. No household data is sent to the guide; its navigation bridge checks the exact origin, frame, open state and destination allowlist.

Receipt scans now separate the product name, receipt amount and stock measurement. Trailing receipt tax codes, package sizes, count/rate lines and weighted products have regression coverage. Prices are displayed separately, unknown quantities are marked as placeholders, and every pantry item starts unselected for review. Expense scans use the same parser for product names and line totals. Ambiguous numeric columns are skipped rather than stored as product names. Existing saved entries are not rewritten.

The offline shell also caches its relative expense helpers. Cache revisions cover guide content as well as scripts/styles. This release does not force page reloads.

## Validation

114 tests passed across the complete suite before the final cache-helper adjustment. The added cache test and 10 related tests subsequently passed. TypeScript and the production build passed. Browser QA used a disposable local household: both guide entry points, search, stepper, checklist persistence, feature jump/return, and a 390px layout without horizontal overflow. Actual Tesseract OCR read a synthetic receipt image and only explicitly selected products were saved as 2 L milk and 5 kg rice. No live household was edited. OCR still requires review and is not certified for every receipt layout or physical phone.

## Publishing and current users

Use the existing Cloudflare Worker, D1 binding, receipt storage, provider configuration and persistent server keys. No migrations, data resets, role changes or key rotations are part of this release. Existing installed users retain the same URL/icon/account. Existing pages continue running until reopened/refreshed. Wait for Family synced before refreshing pending edits.

Build and test against disposable data, retain the source commit and archive, deploy the exact built version, then verify public release/assets/guide headers and signed-in navigation without editing live data. Retain the previous Cloudflare version for code rollback. A code rollback does not reverse user data edits. For a future database migration, design backward compatibility and a separate recovery plan before deploying; code rollback alone is not a database recovery strategy.
