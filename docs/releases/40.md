# OurHouse release 40

Long receipts read locally can use two OCR workers on capable devices when four or more sections need reading. The same bounded pool handles on-device fallback for failed AI sections. Results remain in physical section order, and all workers are terminated after a scan or failure. Short receipts retain the single-worker path. Receipt AI consent, account isolation, source labels and the editable import review are unchanged.

This is a scheduling improvement. A real-phone latency gain and the broader held-out name/quantity/category accuracy goal still need measurement; the private receipt model is not part of this release. No database migration, key rotation, paid compute or new external data flow is included.

Release requires exact-build validation, isolated staging, a rollback dry run and public smoke checks. Prior public release: 39.
